# 网址打不开：DNS 劫持、污染和清缓存

只有某个网址打不开，或者控制台、订阅更新在某个 Wi‑Fi 下打不开，多半是地址查询（DNS）出了问题。先按「先这样做」处理，想了解原因再往下看。

## 先这样做
1. **换手机 4G/5G 再试。** 能打开，问题出在刚才那个 Wi‑Fi 或路由器。
2. **清掉设备记住的错误地址。**
   - iPhone、安卓：打开飞行模式，等 5 秒再关掉。
   - Windows：打开「命令提示符」，运行 `ipconfig /flushdns`。
   - Mac：打开「终端」，运行 `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`。
   - Chrome、Edge：访问 `chrome://net-internals/#dns`，点 **Clear host cache**。
3. **检查有没有绕过应用的设置。**
   - 只有一个浏览器打不开：关掉它的「安全 DNS」再试。Chrome 在 设置 › 隐私和安全 › 安全 › 使用安全 DNS；Firefox 在 设置 › 隐私与安全 › 基于 HTTPS 的 DNS。
   - iPhone 开了 iCloud 专用代理（Private Relay）：在 设置 › Wi‑Fi › 当前网络旁的 ⓘ 里，对这个网络关掉。
   - 设备或路由器里手动填过 DNS 服务器：不确定为什么填的，就删掉，改回「自动获取」。
4. **重启应用**，再试一次。

第 3 步只是临时排查。找到原因后，把你关掉的「安全 DNS」或 iCloud 专用代理重新打开，它们本身是保护隐私的。
5. 浏览器提示「证书错误」「您的连接不是私密连接」，**立刻关掉页面，不要输入密码**。

## DNS 是做什么的
设备打开一个网址之前，要先问 DNS 服务器：「这个网址对应哪个地址？」拿到地址才去连接，就像打电话前先问查号台。平时替你回答的，通常是家里路由器和它背后的宽带运营商。

这一问一答大多**不加密**。互联网标准 RFC 9076 写明：几乎所有 DNS 流量都没有加密，一次查询同时透露了是谁在查、查的是什么。也就是说，只要用的是普通 DNS，你所在的网络就看得到你查了哪些网址。

## 劫持和污染：两种拿到错误答案的方式

| | DNS 劫持 | DNS 污染 |
|---|---|---|
| 谁给了错误答案 | 你正在用的 DNS 服务器，或者被改过的设置 | 路上某个环节抢在真答案前面回答 |
| 影响范围 | 常常是这个网络下很多网站 | 通常只是特定几个网址 |
| 换网络后 | 换手机 4G/5G 通常就好 | 不一定好 |

### 劫持的三种常见情况
1. **查询服务器改了答案。** 负责全球域名的机构 ICANN 下属安全委员会的报告（SAC 032）把这种做法叫「DNS 响应篡改」，点名的提供方包括给用户做域名解析的运营商。表现：输入网址，跳到广告页、导航页或你没想去的页面。
2. **路由器或设备的 DNS 设置被改了。** 路由器用着默认密码、开着远程管理，或者装过来路不明的软件和描述文件，DNS 都可能被改成别人的服务器。表现：这个 Wi‑Fi 下很多网站不对劲，换手机 4G/5G 就好。
3. **公共 Wi‑Fi。** 酒店、咖啡店、图书馆的 Wi‑Fi 通常强制用它指定的 DNS，你控制不了。

### 污染是怎么发生的
普通 DNS 查询不加密，路上任何环节都看得到，也都能抢先回答，设备会接受最先到的答复。有的网络会对特定网址发出伪造答复，伪造的往往先到，给出的地址通向无用之处。表现：只有一个网站打不开，报「连接被重置」「响应时间过长」；能用几分钟又不行。

### 错误的答案为什么会留下来
设备、浏览器和路由器会把答复保存一段时间，伪造的也会被保存。所以就算你已经连上了，错误的地址也可能继续被用，直到缓存被清掉。这就是第 2 步要清缓存的原因。

## 连上我们的线路之后
- **经过应用的查询都加密**（例外见本节最后一条）。订阅里已经设好加密 DNS，路上的设备看不到你查的网址，也塞不进假答案。它们仍能看到你在连一个加密 DNS 服务，但看不到内容。
- **sing-box**：接管设备上全部流量，包括所有 DNS 查询。境外网址经我们的线路在境外查询；国内网址用国内的加密 DNS 直接查，不绕路。
- **Clash Verge Rev、FlClash**：查询同样加密。要走线路的网站，域名交给线路另一端去查，你本地不查。
- **例外：** 电脑上的 Clash Verge Rev 没开 TUN（虚拟网卡）模式时，不走系统代理的软件会用电脑自己的 DNS，仍可能被污染。个别应用不行，打开 TUN 模式。你自己手动填过的 DNS、浏览器的「安全 DNS」，也可能绕过订阅里的设置。

所以劫持和污染主要影响**连上之前**的几步：打开官网、登录控制台、更新订阅。

## 控制台或订阅更新打不开
1. 已经能用的线路先照常用。导入过的线路连的是节点地址，官网打不开一般不影响它。
2. 先在应用里连上，再更新订阅。
3. 还是失败，换手机 4G/5G 更新，或用手机 4G/5G 登录控制台重新导入。
4. 只从控制台拿订阅地址，**不要从别人发来的链接或二维码导入**，见「订阅地址就是你的钥匙」。

## 怀疑路由器被改过
1. 登录路由器管理页面，看「DNS」一栏。正常一般是「自动获取」；填着你不认识的地址，改回「自动获取」，保存后重启路由器。
2. 不确定改了哪里：把路由器恢复出厂设置，重新填宽带账号、设置 Wi‑Fi，换一个新的管理密码。
3. 在电脑上对比：分别在 Wi‑Fi 和手机热点下运行 `nslookup spiritfox.app`，两次给出的地址差别很大，说明其中一边的答案有问题。

## 平时怎么预防
- 改掉路由器的默认管理密码，关闭「远程管理」，有固件更新及时装。
- 路由器和设备的 DNS 保持「自动获取」。
- 不装来路不明的软件、证书和描述文件。
- 安卓的「私人 DNS」保持默认。
- 在公共 Wi‑Fi 下，登录、付款、更新订阅尽量用手机 4G/5G。
- 看到证书警告，永远不要点「继续访问」。

## 更彻底的办法：带验证的 DNS 和加密 DNS
- **DNSSEC（带验证的 DNS）**：标准 RFC 4033 写明，它为 DNS 数据提供来源验证和完整性保护，但不提供保密性。也就是说，它能识破被改过的答案，别人仍看得到你查了什么。
- **加密 DNS（DoH 等）**：标准 RFC 8484 写明，它的主要用途之一是防止路上的设备干扰 DNS，能缓解被动监听，以及把 DNS 流量引到恶意服务器的攻击。我们订阅里用的就是这一类。

这两类要看设备和网络支不支持。普通用户按上面「平时怎么预防」做就够了。

标准原文：`www.rfc-editor.org/rfc/rfc9076`、`rfc4033`、`rfc8484`；ICANN SAC 032 报告在 `icann.org` 安全与稳定咨询委员会（SSAC）报告列表里。
